## 1. 技术栈（已确定，不再讨论选型）

| 成员 | 分工文档中的职责 | 确定技术栈 | 理由 |
|---|---|---|---|
| **A 后端业务系统** | Python TCP Socket 服务端、多客户端连接管理、队列管理、六个业务操作、状态维护与广播 | **Python 3.10+ 标准库**：`socket` + `threading`（每连接一线程）+ `json` + `struct` + `time`。**零第三方依赖** | Socket 编程是本实验考点，标准库最直观；线程模型比 selectors 易读，5～10 个连接量级完全够；不给 A 引入任何安装环节 |
| **B 网页前端系统** | 首页、挂号页、医生叫号页、候诊大屏页、实时状态显示、美化交互 | **原生 HTML + CSS + JavaScript(ES6)**，无框架、无构建工具、无 CDN 外链。统一的 `js/common.js` 封装 WebSocket | 两周周期 + 三人并行，避免 npm/Vue 工具链成为集成瓶颈；离线演示不断网；C 的服务器直接托管静态目录，B 不用自己起服务器 |
| **C 网络通信与辅助模块** | WebSocket 网关、网页↔TCP 转发、JSON 应用层协议、拆包粘包、断线重连、状态恢复、UDP 状态推送 | **Python 3.10+ `aiohttp` + `asyncio`**（`pip install aiohttp`）：`aiohttp.web` 同时提供静态页面托管与 `/ws`，`asyncio.open_connection` 作为 TCP 客户端连 A；UDP 用标准库 `socket` | 单进程异步即可同时管理多条浏览器 WS 与多条到 A 的 TCP 连接；原生支持超时、心跳、重连；静态托管顺带解决 B 的页面加载 |

**统一约定**

- Python 版本 **3.10+**，三人一致；代码跨平台写法，路径用 `/` 或 `pathlib`，不要用硬编码反斜杠。
- 唯一第三方依赖：`aiohttp`（仅 C 需要，安装命令 `pip install aiohttp`）。A、B 零依赖。
- 时间统一 `time.time()`（Unix 秒，float）；JSON 统一 `ensure_ascii=False`、UTF-8 编码、键名小写下划线外的字段按 `PROTOCOL.md` 固定。
- 数据全部为**虚构号码与模拟数据**（选题说明要求），不接数据库、不做用户登录、不做持久化。

> 备选降级（仅在 aiohttp 装不上时启用，需三人同意）：C 改用 `websockets` 库 + `python -m http.server`；此时页面与 WS 分端口，`PROTOCOL.md` 的 WS 侧约定不变。

## 2. 系统架构

```
   浏览器（成员 B，4~5 个页面 / 多个 tab）
   ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
   │ index    │ │ register │ │ doctor   │ │ display  │  ┌──────────┐
   │ 首页导航 │ │ 挂号页   │ │ 医生叫号 │ │ 候诊大屏 │  │ net 页   │
   └────┬─────┘ └────┬─────┘ └────┬─────┘ └────┬─────┘  │ 网络信息 │
        └────────────┴─────┬──────┴────────────┘         └────┬─────┘
                           │  WebSocket  ws://host:8080/ws?role=...
                           │  每条 WS 一个 JSON 对象（WS 自带消息边界）
                    ┌──────▼─────────────────────────────────────▼──────┐
                    │   成员 C：aiohttp 网关（协议所有者 / 埋点采集）     │
                    │   · 静态页面托管（指向 web/）                       │
                    │   · 1 条 WS ↔ 1 条 TCP 连接映射                    │
                    │   · JSON 编解码、长度前缀帧、req_id 登记、超时重试   │
                    │   · 断线重连 + RESYNC 状态恢复                       │
                    │   · 指标采集 → metrics.json / GET /api/metrics       │
                    └───┬───────────────────────────────────┬───────────┘
                        │ TCP 127.0.0.1:9000                │ UDP 127.0.0.1:9001
                        │ 4B 大端长度前缀 + UTF-8 JSON       │ 状态副本（仅对照实验）
                        │ 多条独立连接，每条代表一个浏览器 tab │ → C 自己的 udp_probe 统计
                    ┌───▼───────────────────────────┐  ┌────▼─────┐
                    │ 成员 A：Python TCP 服务端      │  │ udp_probe│
                    │ · threading 每连接一线程        │  │ (C 内部) │
                    │ · 唯一权威队列状态 + Lock       │  └──────────┘
                    │ · 六个业务操作 + ACK + 广播     │
                    │ · seq 单调递增分配              │
                    └───────────────────────────────┘
```

### 关键设计决策

| 决策 | 结论 | 理由 |
|---|---|---|
| **连接模型** | **1 条浏览器 WS ↔ 1 条到 A 的独立 TCP 连接**，由 C 建立并透传 `role` | 让 A 的「多客户端连接管理」和选题说明的「并发客户端通信」真实成立；演示场景 4「多个浏览器窗口」直接对应 A 端多连接；单个页面断线不影响其他连接 |
| **队列状态归属** | **只有 A 存一份**，B 只渲染、C 只转发，均不得本地推算队列 | 选题说明明确要求「服务端统一维护队列状态，避免客户端状态不一致」 |
| **协议所有者** | **C**（分工文档写明 JSON 应用层协议归 C），A / B 只读契约 | 避免三方各自定义字段；C 同时是两条链路的中介，最适合定协议 |
| **UDP 定位** | 仅 C 内部的「状态副本 → 本地 probe」对照通道，**不进主链路、不进浏览器、A 不实现 UDP** | 浏览器不支持 UDP；选题说明要求「UDP 用于非关键状态更新实验，关键叫号操作保留 TCP 确认」；这样 A、B 完全不被牵扯 |
| **B 的独立开发** | C 的网关必须提供 **`--mock` 模式**：内置假队列状态，不连 A 也能返回全套协议消息 | 否则 B 被 C / A 阻塞，违背「各做各的最后合并」 |

### 启动与停止

启动顺序 **A → C → 浏览器**；停止顺序相反。
C 以 `--mock` 启动时只托管页面 + 返回假状态，供 B 独立开发；联调时去掉该参数连真实 A。

## 3. 网络地址与端口（写死，不要各定各的）

| 用途 | 绑定地址 | 协议 | 谁监听 |
|---|---|---|---|
| 页面 + WebSocket | `0.0.0.0:8080` | HTTP / WS | C |
| WebSocket 端点 | `ws://<host>:8080/ws?role=<role>&room=<room>` | WS | C |
| 静态页面根 | `http://<host>:8080/` → `web/` | HTTP | C 托管 B 的文件 |
| 指标接口 | `http://<host>:8080/api/metrics` | HTTP GET | C |
| 网关 → 服务端 | `127.0.0.1:9000` | TCP（长度前缀帧） | A |
| UDP 对照通道 | `127.0.0.1:9001` | UDP（单向） | C 的 probe |

- 本机演示用 `127.0.0.1` 即可覆盖分工文档的全部六个场景。
- 若用多台局域网设备演示，C 绑 `0.0.0.0` 已满足；注意 Windows 防火墙放行 8080。A 只绑回环，不对外暴露。
- 端口占用时的排查顺序：9000（A）→ 8080（C）→ 9001（probe）。

## 6. 集成检查清单（周日联调逐条打勾）

1. **A 自测**（不依赖 B/C）：按 `PROTOCOL.md` 的帧示例手写一条请求发到 9000，验证 `ACK` 与 `STATE_UPDATE` 的 `seq` 递增；用两条连接验证广播。
2. **C 自测**（不依赖 A/B）：`--mock` 模式起服务，用浏览器或 WS 客户端验证收发、半包/粘包、`/api/metrics` 输出。
3. **B 自测**（不依赖 A/C）：连 C 的 `--mock`，四个页面能加载、能收假状态并渲染、`net.html` 能显示 `METRICS`。
4. **正式集成**：按 A → C（去掉 `--mock`）→ 浏览器顺序启动；观察 C 日志中 `HELLO / HELLO_ACK` 成功、A 端连接数 = 浏览器 tab 数。
5. **按 `PROTOCOL.md` 第 9 节的六场景逐条走一遍**，用 `req_id` 与 `seq` 对账；任一环节对不上只看这两个字段，不靠肉眼猜。
6. **跑指标**：让 C 采集并落盘 `metrics.json`，确认五个报告指标都有真实数值（示例值 15 ms / 20 ms 不得直接写进报告）。
7. **演示彩排**：录一段全流程备份视频，现场网络异常时兜底。
